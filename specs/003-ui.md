# 003 — Interface mínima de corridas

Estado: implementada; build de produção passou; fluxo integrado pendente de validação.

## Objetivo

Permitir demonstrar o fluxo de passageiro e motorista no navegador usando os endpoints da API existente.

## Comportamentos

- A UI permite criar conta como `passageiro` ou `motorista`, entrar com email/senha e sair. O ID UUID é criado e persistido pelo backend; JWT fica em memória no navegador.
- Cadastro autentica a pessoa imediatamente. Login recupera o perfil persistido; não permite escolher nem forjar o perfil.
- Passageiro cria uma corrida informando origem e destino. A UI gera `Idempotency-Key`, exibe o resultado e mantém IDs criados nesta sessão.
- O usuário informa ou seleciona um ID para consultar o estado atual periodicamente.
- Motorista altera o estado para a próxima etapa permitida. A autorização continua sendo decidida pela API.
- Erros HTTP são apresentados ao usuário; a UI não tenta inferir permissões pelo conteúdo do JWT.
- A UI configura a URL da API por variável de ambiente e usa proxy same-origin no Compose.

## Fora de escopo

Verificação/recuperação de email e senha, autenticação multifator, roteamento geográfico, acessibilidade auditada e design responsivo além do necessário para a demonstração.
